/   a. the sym refers to the table schema defined in tick/sym.q
/   b. the . specifies the location of the logfile and a symYYYY.MM.DD file is created
/      this file is only really required for the day until the plant executes a .u.endofday[] and persists the rdb's data to the hdb
/   c. feed plant lists not tables which triggers call to .u.upd 
/   d. .u.upd async pushes list (`upd;Table;data) to rdb which calls value on it (usually upd:insert but see 2g. for clever upd definition)
/   e. note: .u.upd is defined on the tickerplant and upd on the rdb

/7. start logfile replay process example : q tick/sym.q
/   a. define upd:insert
/   b. test log access : count get `:sym2018.04.22
/   c. replay log : -11! `:sym2018.04.22
/   NOTE: .u.rep take 2 parameters and is responsible for replaying the logfile on the rdb
/      i.  a dictionary of table names mapped to their schemas
/      ii. a pair of the number of messages written and the logfile name
/   NOTE: .u.rep is called on the last line of r.q
/       / connect to ticker plant for (schema;(logcount;log))
/       .u.rep .(hopen `$":",.u.x 0)"(.u.sub[`;`];`.u `i`L)";
/   d. some important variables:
/      i.   .u.l : logfile handle
/      ii.  .u.L : logfile path
/      iii. .u.i : message count
/      iv.  .u.j : .u.i + memory buffer = count of messages in tickerplant
/   e. speed of replay of logfile:
/      i.   size of logfile (# msgs)
/      ii.  speed of disk
/      iii. efficiency of .u.upd
/   f. for recovery of rdb simply restart process - it connects to tickerplant and gets .u.L/.u.i which it will replay using -11! in .u.rep
/   g. important difference between -11!`:tplog and value each get 1:tplog i.e. streaming so less memory whereas get pulls entire tplog into memory
/   h. in case of corruption -11!(-2;`:tplog) will return two numbers instead of one:
/      i.  valid n chunks - which can be replayed using -11!(n;`:tplog)
/      ii. valid m bytes
/8. events at end-of-day or rollover i.e. how tp and hdb and rdb communicate:
/   a. tickerplant calls .u.endofday which triggers .u.end on all subscribers
/   b. rdb's call to .u.end calls .Q.hdpf[hdbport;directory;partition;`p#field] on all in-memory tables which:
/        i.   calls .Q.dpft[directory;partition;`p#field;tablename] on rdb saving splayed tables to disk parition specified
/        ii.  clears tables on rdb
/        iii. sends a table reload to hdb on port .u.x[1] which should be hdb (default 5012)

/ 1. Building Real-Time TickSubscribers - Nathan Perrem, Kx Corp - August 2014p
/              url : https://code.kx.com/q/wp/building_real_time_tick_subscribers.pdf
/    Summary : Perrem's excellent paper is a good introduction to standard ticker plant architecture. A must read.
/              Chapter 4 covers how to build a custom temporally joined trade aj quote architecture with it's own binary logfile.
/ 2. Order Book: a kdb+ Intraday Storageand Access Methodolog - Niall Coulter - Kx Corp - y
/              url : https://code.kx.com/q/wp/order_book_a_kdb_intraday_storage_and_access_methodology.pdf
/    Summary : Coulter covers the fine balance between processing/storage of an order book and it's subsequent retrieval & analysis.
/              Different trade table schemas and accessor functions are presented and dicussed.

/
